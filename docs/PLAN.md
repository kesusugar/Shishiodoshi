# ししおどし リアル再現プラン

参考画像: [ref1（ししおどし全景）](reference/ref1-shishiodoshi.png) / [ref2（苔むした手水鉢と筧）](reference/ref2-kakei-moss-basin.png)

## 0. 基本方針

「それっぽく動くアニメーション」ではなく、**物理から見た目も音も生まれる**作りにする。

- 竹の動き: 決まった周期で回すのではなく、竹と水の重さによる**回転運動を実際に計算**する。周期・倒れる速さ・跳ね返り・コツンの強さは全部そこから決まる
- 水の見た目: 水量や流速などの**計算結果から描く**（筒の中の水位、注ぎ出す水の太さ、鉢の波紋）
- 音: 録音素材を貼るのではなく、**同じ物理イベントから音を合成**する（竹の共鳴、気泡の音、筒が満ちるにつれて上がる音程）
- 検証: ヘッドレス Chromium でスクリーンショットを撮って参考画像と見比べる。音はオフライン合成して波形・スペクトログラムで確かめる。**「目と耳で確かめてから次へ」**を各段階の条件にする

ChatGPT の案（決まった順に状態を切り替える方式）は使わない。状態は物理計算の結果として自然に現れるだけにする。

## 2. 技術スタック

- **Vite + TypeScript**（型付きのまま物理・音・描画を分けて書く）
- **three.js（WebGL2）** と自作の GLSL。WebGPU は使わない。ヘッドレス検証（SwiftShader）で確実に動かすため
- **Web Audio API + AudioWorklet** で音を即時合成（素材ファイルに頼らない）
- **Vitest**（物理の単体テスト）、**Playwright**（スクリーンショット・パフォーマンス計測・音声の書き出し）
- 素材: ambientCG（CC0）の岩・苔・土のスキャンテクスチャ、Poly Haven（CC0）の HDRI。取れなければ手続き生成に切り替える
  - 確認済み: npm・ambientCG・Poly Haven の API には接続できる。dl.polyhaven.org は一時的に 521 エラー

## 3. 構成（レイヤー）

```
src/
  sim/          物理（描画・音から独立。決定論的・固定ステップ）
    rigidBody.ts      竹筒の回転運動、軸の摩擦、当たり石との衝突
    tubeHydro.ts      筒内の水: 容量・重心・水面を角度と水量から求める早見表
    stream.ts         筧から落ちる水の軌道と、筒に入るか外れるかの判定
    spill.ts          口からあふれ出る流量
    basinWaves.ts     鉢の水面の波（GPU、下を参照）
    events.ts         衝突・着水・注ぎ出しなどのイベント（音と描画が受け取る）
  render/       three.js の描画
  audio/        合成エンジン（AudioWorklet）
  scene/        地形・配置・カメラ
  debug/        グラフ・操作パネル（lil-gui）
tools/          オフライン検証スクリプト（撮影・音声書き出し・スペクトログラム）
```

物理は描画の fps に関係なく **240Hz 固定ステップ**で回す。音のイベントには物理時刻を付けて、AudioContext の時刻に対応づけて予約する。これで描画が一瞬止まっても、コツンの鳴るタイミングはずれない。

## 4. 物理モデル（リアルさの土台）

### 4.1 筒の中の水
- 筒の内側を「斜めに切った口 ＋ 節で閉じた底 ＋ 肉厚のある円筒」として正確に形にする
- 事前に**角度 θ と水量 V ごとの表**を数値計算で作っておく
  - その角度で入る最大量
  - 水の重心（回す力の計算に使う）
  - 水面の高さ（描画に使う）
  - 口の縁から上に出ている水の高さ h
- 水面は常に水平…ではなく、**揺れ（スロッシング）を減衰振動で遅らせる**。倒れ始めた瞬間に水が後ろに寄る感じを出す

### 4.2 竹筒の回転
- 回す力 = 竹の重さ（重心はあらかじめ計算）＋ 水の重さ（表から）
- 回りにくさ = 竹の分 ＋ 水の分（水量で変わる）
- 軸の摩擦（転がり摩擦と、速さに比例する粘性摩擦）
- **当たり石との衝突**: 反発係数と接触の柔らかさで扱う。当たる速さを記録して、それがコツンの強さになる。何度か小さく跳ねるのも自然に出る
- 前側の止め（横木や地面）にも同じ扱いで当てる

### 4.3 水の出入り
- 入る水: 筧から一定流量。水は**放物線で落ちる**ので、**筒が傾くと水が筒の外に落ちる**（外側や鉢に当たって音と見た目が変わる。本物っぽさに大きく効く）
- 出る水: 縁を越える高さ h から、堰の式 Q = C·w·h^1.5 で流量を出す。出ていく水の勢いは、そのまま注ぎ出す水の粒子の初速になる
- 物理量の単位は実物の寸法に合わせる（筒は長さ 60–80cm・直径 6–8cm、流量は 20–60 mL/s ほど）。周期がだいたい 10〜40 秒になるように調整する

### 4.4 テスト（Vitest）
- 水量が保存される（入った量 = 出た量 + 溜まった量）
- 周期が流量に対して単調に変わる
- 衝突でエネルギーが増えない
- 同じ入力なら同じ結果になる

## 5. 水の描画

| 対象 | 手法 |
|---|---|
| 筧から落ちる流れ | 放物線に沿った管状のメッシュ。流れが速くなるほど細くなる（流量が一定なので）。表面のくびれ、途中から粒に分かれる、屈折・フレネル反射 |
| 筒の中の水面 | 表から出した水面を筒の内側で切り抜く。流れが落ちる点に小さな波紋 |
| 注ぎ出す水 | GPU 粒子を口の縁から出す → **画面上で流体として描く**（深度を描いて、形を保ったままぼかし、法線を出して、屈折と厚みによる色の吸収を付ける）。一枚の水の膜が粒に分かれる様子まで出す |
| 鉢の水面 | **caustic-volume の iWave を移植**（11章）。鉢の形のマスク付き、256² 程度。水滴・流れ・注ぎ出しの着水点から波を立てる。周りの反射（映り込みの計算＋HDRI）、底の屈折、**底に揺れる光の模様（コースティクス。caustic-volume Lite の方式）** |
| あふれる水 | 鉢の切り欠きから薄い水膜が石の表面を伝って流れる（流れて見えるテクスチャ） |
| 浮かぶ葉 | ref1 のように数枚。水面の流れに乗って漂う |
| 濡れ | 石や竹に「濡れ具合」を持たせる。濡れると暗く・つるっと見える。しぶきで濡れて、時間とともに乾く |

## 6. 素材・光・画面処理

- **竹**: 手続き生成で作る。節の輪、縦の筋、ろうのような光沢のある表面（塗装のようなツヤの層）、切り口の繊維、古びた色の変化（ref1 は枯れた黄土色）。光が少し透ける感じも近似する
- **岩・鉢**: スキャンテクスチャ＋細かい凹凸、ref2 の苔（上向きの面や縁に生える。毛羽立ちを出す）
- **光**: HDRI の周り光 ＋ 太陽光。**葉を通した木漏れ日の模様**、柔らかい影、隙間の暗さ
- **画面処理**: AgX の色調、控えめな光のにじみ、**被写界深度**（ref2 のボケ）、ちらつき除去、色収差やビネットは控えめに
- **植物**: 葉を大量に並べて、風で揺らす（音の風と同じ値で動かす）
- **品質設定**: 高・中・低（波の細かさ、粒子の数、影、被写界深度の切り替え）

## 7. 音（本物らしさへの一番効く手段）

AudioWorklet で全部合成する。物理イベントを受けて鳴らす。

1. **コツン（竹が石に当たる音）**: 竹筒の振動をいくつかの固有の響きの重ね合わせで作る
   - 竹の管が曲がって震える響き（いくつかの周波数と減衰の組）
   - **管の中の空気の共鳴**（底が閉じた管なので 周波数 ≈ 音速 / (4 × 空気の長さ)）。水が残っていれば空気の長さが短くなり、音色が変わる
   - 石に当たる瞬間の短い雑音と、竹の硬い「カッ」
   - 当たる速さで音量と明るさを変える。**跳ね返りの小さな二打目**も物理から自然に出る
2. **水の音（気泡の合成）**: 水滴が水面に落ちて気泡ができると「ポチャ」「プク」と鳴る（周波数は気泡の大きさで決まり、少し上がっていく）
   - 筧の流れが鉢や筒の水に当たる → 気泡をまとまった数だけランダムに発生
   - **筒が満ちるにつれて、筒の中の響きの音程が上がる**（瓶に水を注ぐときと同じ。本物っぽさに一番効く）
   - 注ぎ出しの瞬間は、気泡の数を一気に増やし、ザッという雑音を重ねる
   - 竹が傾いて水が外れる間は、音の落ちる場所と性質が変わる
3. **空間**: 頭の形を考慮した左右の聞こえ方（HRTF）、距離による減衰、**庭の反響**（屋外なので反射は少なめ。岩からの近い反射と短い残響を自作の反響データで）
4. **環境音**: 葉の揺れる音（強弱のある風）。鳥は作り物感が出やすいので、入れるか・切り替えにするかは後で判断
5. **検証**: オフラインで WAV を書き出し、スペクトログラムの画像を作って見て確かめる。必要なら freesound の公開試聴音源をダウンロードして、**周波数と減衰の調整の参考だけ**に使う（配布物には含めない）

音を始めるには、ユーザーのクリックなどの操作が必要（ブラウザの制約）。最初に「クリックで開始」の画面を出す。

## 9. 進め方と確認条件

各段階の終わりに、スクリーンショット / 音声 / テスト / fps を確認してからコミットする。

| 段階 | 内容 | 確認条件 |
|---|---|---|
| **P0 下準備** | Vite+TS+three の雛形、ヘッドレスで WebGL が描画できるか確認（caustic-volume のテストと同じ起動オプションを使う）、撮影・計測スクリプト | ヘッドレスでスクリーンショットが撮れる |
| **P1 物理** | 4章すべて＋テスト。仮の形で動きを見られるようにする | テストが通る。周期・跳ね返りがグラフで自然に見える |
| **P2 音の最小版** | コツン＋気泡の水音＋満ちるにつれて上がる音程を、物理イベントで鳴らす | 書き出した WAV とスペクトログラムで、響き・減衰・時間のずれを確認 |
| **P3 形と素材** | 竹・支柱・鉢・岩・植物、光、HDRI | ref1 と並べて比べ、構図と質感が近い |
| **P4 水の描画** | 5章（流れ → 鉢の波とコースティクス → 注ぎ出す水の粒子 → 濡れ） | 静止画と動画で、流れの細さ・粒への分かれ方・注ぎ出しが自然 |
| **P5 仕上げ** | 画面処理、木漏れ日、風、空間的な音、反響、UI | 中程度の GPU で 60fps（高品質）。低品質なら内蔵 GPU でも動く |
| **P6 公開** | ビルドして Artifact（claude.ai のページ）かリポジトリの Pages で見られるようにする | 実際のブラウザでちゃんと再生される |

各段階は小さく刻んでコミットする。P1〜P2 だけでも「本物の動きと音がするししおどし」として完成しているようにする。

## 10. 先に知っておくべきリスクと対策

- **ヘッドレスは GPU を使わず遅い**: 見た目の確認は静止フレームを中心にする。fps の最終確認はあなたの実機ブラウザでお願いする
- **音の良し悪しを最後に判断するのは耳**: 私は波形とスペクトルで確かめるところまで。最後の聞き心地の調整は、あなたの感想をもらって直す
- **注ぎ出す水を画面上で流体として描くのは重い**: 低品質では粒子の数を減らすか、薄い膜のメッシュで代わりにする
- **素材がダウンロードできない場合**: 竹は最初から手続き生成で作る予定。岩も手続き生成で作れるようにしておく

## 11. caustic-volume からの取り込み

[ScottieFox/caustic-volume](https://github.com/ScottieFox/caustic-volume)（MIT、three.js r186、WebGL2）のコードを読んだうえでの判断です。**水面の計算と水の光の扱いは、そのまま移植する価値があります。**ただし向こうは「水槽を上から照らす」デモで、こちらは「屋外の小さな鉢と、流れて注ぐ水」です。使う部分は選びます。

### 取り込むもの

| 部分 | 向こうの実装 | こちらでの使い方 |
|---|---|---|
| **水面の波（iWave）** | `sandbox/src/10_sim.js` の `SH.ripple`。Tessendorf の iWave 方式で、13×13 の重みを使って波の広がりを計算する。ただの波の方程式より、**小さい波ほど速く進む**という本物の水の性質が出る。粘性による減衰、細かいギザギザを消す処理もある | 鉢の水面と筒の中の水面に使う。向こうは四角い水槽の壁で跳ね返るだけなので、**鉢の形（丸くていびつな縁）のマスク**を足して、縁で跳ね返るようにする |
| **物が水を押しのける計算** | 物が「前にいた場所」と「今いる場所」の差を水面に足して、波紋や航跡にする（`column` / `uSphOld` / `uSphNew`）。一瞬の衝撃（`uImp`）も同じ仕組み | 水滴の着水、流れが当たる点、注ぎ出しの水、浮かぶ葉に使う。**4章の物理計算から着水の位置と量をそのまま渡す** |
| **底の光の模様（コースティクス）** | Lite の `causMesh`。水面の細かい格子から光を1本ずつ底に落とし、光が集まる度合いを面積の比で出す | 鉢の底に使う。鉢は浅くて小さいので Lite の方式で十分で、軽い。木漏れ日の模様と掛け合わせる |
| **水の光の扱い** | 反射の強さ（Fresnel の正確な式）、屈折（Snell）、全反射、水が赤い光から吸収していく性質（Beer–Lambert） | 鉢・流れ・注ぎ出し・筒の中、全部の水の見た目で共通の関数にする |
| **画面処理と負荷調整** | ちらつき除去（TAA）・被写界深度・光のにじみ（`40_post.js`）、fps を見て描画解像度を自動で上げ下げ | 6章の画面処理と品質設定の土台にする |
| **ヘッドレス検証** | Playwright + ソフトウェア描画（`--use-angle=swiftshader --enable-unsafe-swiftshader` など）で数視点を撮影し、シェーダーのエラーで失敗させる | P0 の検証の仕組みにそのまま使う（Chrome 141 以降はこの指定がないと、GPU のない Linux で WebGL が動かない） |

### 取り込まないもの

- **FFT の海の波**: 手水鉢には風が作るうねりはない。そよ風のさざ波がほしくなったら、Lite の「小さな波をいくつか重ねる」方式を、ごく弱くして使う
- **光の筋（caustic volume）、インク、砂、生き物、レーザー、浮き沈みする物体**: ししおどしには関係ない

### 移し方
- 向こうはビルドなしの1ファイル構成。こちらは Vite + TypeScript のモジュールに分けて移植する。シェーダーは `src/render/water/` にまとめる
- MIT ライセンスなので、移植したファイルの冒頭に元の著作権表示を書く。`THIRD_PARTY_NOTICES.md` にライセンス全文を入れる
- 移植した直後に「クリックで波紋」だけの確認用シーンを作って、元のデモと同じように動くことを確かめてから、鉢の形に作り変える

### 進め方への影響
- **P4（水の描画）が軽くなる**: 鉢の水面とコースティクスは、ほぼ移植と調整で済む。浮いた手間は、**注ぎ出す水の描画**（向こうにはない、一番難しい部分）と**濡れの表現**に回す
- iWave は P1（物理）の時点で先に入れておく。着水のイベントが波として見えるようにして、物理と見た目のつながりを早い段階で確かめる

## 12. 決めてほしいこと

1. **動かす環境**: PC ブラウザ専用か、スマホでも動かしたいか（品質の上限が変わる）
2. **音**: 全部合成でいくか、あとで実際に録った音と差し替えられるようにしておくか
3. **構図**: ref1 のまま（岩場・枯れた竹）か、ref2 寄り（苔・新しい竹・明るい木漏れ日）か、両方を切り替えられるようにするか
4. **公開方法**: GitHub Pages か、claude.ai の Artifact か
